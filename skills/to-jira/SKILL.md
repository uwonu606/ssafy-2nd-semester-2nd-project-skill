# to-jira

설계 문서를 Jira 하위 작업으로 옮긴다. **bottom-up 이다** — 문서 목차를 따라 내려가지 않고, 해야 할 일을 먼저 다 쪼갠 다음 그것들을 스토리로 묶는다.

**하위 작업 하나는 브랜치 하나다.** 이 스킬이 정하는 것은 *무엇을 할당하나*이지 *어떻게 구현하나*가 아니다. 구현은 구현할 때 고민한다.

**입력은 문서 경로 하나다.** 인자가 없으면 대화 맥락에서 대상 문서를 잡고, 그것도 없으면 사용자에게 묻는다. 대상 문서가 확정되기 전에는 다음 단계로 가지 않는다.

**재실행이면 [`references/rerun.md`](references/rerun.md) 를 읽는다.** 재실행인지는 1단계에서 판별된다 — 그전에는 읽지 않는다.

## 1. 환경을 읽는다

Jira 환경 사실은 이 문서에 없다. **어디를 봐야 하는지만 적혀 있고 무엇이 있는지는 매번 읽는다** — 프로젝트 키도 에픽 목록도 낡는다. Atlassian MCP 도구(JQL 검색)로 아래를 채운다.

- **대상 프로젝트 키** — 접근 가능한 프로젝트가 여럿이면 사용자에게 확인받는다.
- **이슈 타입 계층** — 에픽 / 스토리 / 하위 작업 세 층이 실제로 쓰이는지, 각 층의 타입 이름이 무엇인지.
- **에픽 전량** — 키와 제목. 3단계에서 고를 후보다.
- **스토리 전량** — 키·제목·부모 에픽.
- **기존 하위 작업의 관행** — 제목 접두어와 라벨 어휘, 그리고 **크기**. 기존 하위 작업 하나가 곧 이 팀의 브랜치 하나다. 2단계에서 크기의 기준으로 쓴다.
- **문서 라벨로 기존 이슈 검색** — 문서 라벨의 기본값은 문서 파일명 스템이다 (`pipeline-core.md` → `pipeline-core`).

**Atlassian MCP 도구가 없으면 여기서 멈추고 사용자에게 알린다.** 이 스킬은 MCP 없이 할 수 있는 일이 없다.

문서 라벨로 검색된 이슈가 1건 이상이면 **재실행**이다. [`references/rerun.md`](references/rerun.md) 를 읽고 그 분기를 아래 단계에 겹쳐 적용한다.

**완료 기준**: 위 목록이 다 채워졌고, 재실행인지 아닌지가 판별됐다.

## 2. 태스크 초안을 부품 단위로 뽑는다

**태스크 하나 = 브랜치 하나 = 부품 하나.** 부품은 다른 부품과 **저장된 산출물(테이블)이나 인터페이스로만** 통신하는 덩어리다. 설계 문서의 단계 경계와 seam(교체 지점)이 그대로 부품 경계다. 부품 안의 내부 단계 — 입력 조립·출력 파싱·저장·버전 산출 같은 것 — 는 나누지 않는다. 그건 구현 분해도이고, 구현은 구현할 때 고민한다.

태스크마다 **완료 기준 한 줄**이 서야 한다. 그 한 줄은 "부품이 돌아간다"를 말한다 — *"기사 하나를 넣으면 extraction 행과 new_candidate 행이 나온다"*. 판정에 다른 태스크가 필요 없어야 하고(입력은 고정 자료로 대신한다), 코드가 판정한다. **시간 추정은 쓰지 않는다** — 문서만 읽고 "1.5일"이라 적으면 그건 지어낸 숫자다.

| 나누는 신호 | 예 |
|---|---|
| 테이블·인터페이스 경계를 넘는다 | 매칭기 → `mention` → 추출기. 둘이다 |
| 같은 인터페이스의 구현체가 여럿이라 사람이 나눠 맡을 수 있다 | 매체 어댑터 4종. 단, 몇 건으로 묶을지는 사람이 정한다 — 표에 ⚠️ |

| 합치는 신호 | 예 |
|---|---|
| 한 부품의 내부 단계 | 입력 조립 · 출력 검증 · 배치 제출 → 추출기 하나 |
| 한 부품의 부속 규칙 | 표면형 등록 규칙 → 사전 도구에 흡수 |
| 코드가 없는 실행 | 3개월 백필 → 브랜치가 없다. 그 결과를 내는 부품의 완료 기준에 흡수한다 — *"8개 매체 3개월치가 article 에 있다"* |
| 공통 기반과 구현체가 서로 있어야 검증된다 | 크롤러 공통 기반 + 어댑터 4종 → 한 브랜치. 기반은 구현체가 있어야 인터페이스가 굳고, 구현체는 기반이 있어야 돌아간다 |
| 행동이 없는 공통 층 | 저장 접속·설정 → 첫 소비자 브랜치가 만들고 이후 부품이 따른다. 테이블은 그 테이블에 처음 쓰는 부품 몫이다. 소비자 없는 스키마 브랜치는 컬럼 없는 DDL 을 만든다 |
| 오케스트레이터가 맡는 것 | 스케줄·재시도·대기가 Airflow 같은 오케스트레이터 몫이면 "서버화" 부품은 없다. 각 부품이 자기 DAG 를 갖고, 오케스트레이터 구성이 첫 부품보다 앞선다 |

**접속사는 신호가 아니다.** "조립하고 검증한다"는 한 부품의 두 단계다. 접속사가 갈라놓는 두 쪽이 **서로 다른 부품일 때만** 나눈다.

**크기는 기존 하위 작업과 견준다.** 1단계에서 읽은 기존 하위 작업 하나가 이 팀의 브랜치 하나다. 뽑은 태스크가 그보다 눈에 띄게 잘면 부품이 아니라 함수를 세고 있는 것이다. 합친다.

**부품 수는 문서의 단계 수 + seam 수 근처다.** 그 두 배를 넘으면 함수를 세고 있는 것이다. 문서가 단계 5개와 seam 5개를 그렸는데 태스크가 39개면 그 자리에서 멈춘다.

**품질은 완료 기준이 아니다.** "사전이 충분한가", "추출이 정확한가"는 태스크에 안 쓴다. 끌어오면 닫을 수 없는 이슈가 된다. 태스크 완료는 **만들어졌나**까지다.

**조사는 독립 태스크로 안 뗀다.** 조사만 떼면 완료 기준이 "알아냈다"가 되어 코드가 안 붙는다. 그 조사가 필요한 부품에 흡수시키고 "조사 결과를 이슈에 남긴다"를 경계에 적는다.

**코드로 안 넘어오는 사람 판단은 스토리로 올린다.** 태스크는 코드가 닫는 데까지 쓰고, 사람이 눈으로 보고 판정하는 몫은 그 태스크들을 묶는 **새 스토리의 완료 조건**으로 올린다. 태스크는 전부 코드 판정이라는 규칙이 서고, 사람 판단은 사라지지 않고 한 층 위에 남는다. 이건 **새로 만드는 스토리에만** 쓴다 — 기존 스토리는 안 건드린다.

**완료 기준**: 문서의 할 일이 전부 부품 단위 태스크가 됐고, 각 태스크에 완료 기준 한 줄이 붙었다.

## 3. 태스크를 스토리에 매핑한다

| 층 | 이 스킬이 |
|---|---|
| **에픽** | **절대 만들지 않는다.** 1단계에서 읽은 기존 에픽 중에서 고른다 |
| **스토리** | 기존 것에 붙이는 게 기본. 어느 것에도 안 덮이면 새로 제안하고 **승인**받는다 |
| **하위 작업** | 자유롭게 만든다 |

**새 스토리는 사용자 줄이 서야 만든다.** 첫 줄에서 "사용자"를 지워도 멀쩡하면 스토리가 아니다 — "모든 부품이 여기 쓴다"는 사용자가 아니다. 그런 태스크는 부품이 아니거나(저장 계층) 다른 스토리 소속이다. 흡수하거나 옮긴다.

**에픽 질문은 새 스토리를 만들 때만 생긴다.** 기존 스토리에 붙으면 에픽은 그 스토리의 부모로 이미 정해져 있다.

새 스토리의 에픽은 이렇게 정한다.

- 후보가 하나로 수렴하면 — 매핑표에 **제안 에픽**을 실어 4단계에서 함께 확정받는다.
- 후보가 둘 이상 비등하거나 어느 에픽에도 안 들어맞으면 — ⚠️ 갈림길로 분류해 5단계에서 묻는다.

**완료 기준**: 모든 태스크에 부모 스토리가 정해졌고, 새 스토리마다 에픽이 정해졌거나 ⚠️ 갈림길로 분류됐다.

## 4. 매핑표를 한 장으로 낸다

태스크 전량을 **한 장**에 담아 제시한다. 태스크마다 부모 스토리(기존 키 또는 새 스토리 제안), 파트, ⚠️ 표시를 싣는다.

표 머리에 이번 실행의 **문서 라벨**을 적는다 — 재실행 때 이 라벨로 이슈를 찾으므로, 문서를 개명했거나 앞 실행과 라벨을 잇고 싶으면 사람이 여기서 고친다.

표 아래에 **점검 흔적** 구역을 붙인다.

```
쪼갠 것        크롤러 / 매칭기 / 추출기 → 3건 · 테이블 경계
합친 것        입력 조립·출력 검증·배치 제출 → [DATA] 추출기 구현 1건 · 한 부품의 내부 단계
               크롤러 공통 기반 + 어댑터 4종 → 1건 · 서로 있어야 검증되는 양방향 의존
               저장 접속 계층 → 크롤러에 흡수 · 행동 없는 공통 층은 첫 소비자 몫
흡수한 실행     3개월 백필 → 크롤러 완료 기준 · 브랜치가 없다
방법으로 뺀 것   발굴기 공통 어댑터 · mine() 시그니처 · 어댑터 4종 분류 · Aho-Corasick → 문서 서술의 한 방법. 수행자 몫
⚠️ 갈림길      어댑터를 크롤러에 합칠지 따로 둘지 · 사람이 나눠 맡을지에 달렸다
```

**이 구역이 비어 있으면 점검을 안 한 것이다.** 합친 것이 0건이면 구현 분해도를 그대로 옮긴 것이고, 방법으로 뺀 것이 0건이면 문서 서술을 그대로 옮긴 것이고, 흡수한 실행이 0건이면 문서에 실행 단계가 없었는지 다시 본다.

여기서 사람이 자유롭게 수정한다. 고쳐서 돌려주면 그대로 반영한다.

**완료 기준**: 사람이 표를 승인했다.

## 5. ⚠️ 갈림길만 AskUserQuestion 으로 묻는다

표에 ⚠️ 로 남은 것 중 **진짜 갈림길만** 묻는다. 회당 최대 4문항, 전체로 한두 번.

**태스크마다 순회하며 묻지 않는다.** 25~40번 묻게 되면 사람이 전체를 못 본 채 하나씩 판정하고, "이거 너무 잘게 쪼갰는데"를 알아채는 순간이 영영 안 온다. AskUserQuestion 은 선택지를 좁히는 도구라 갈림길에만 쓴다.

**완료 기준**: ⚠️ 가 전부 해소됐다 — 답을 받았거나, 사람이 표에서 직접 고쳤다.

## 6. 이슈 본문을 쓴다

**자족성이 기준이되, 설계 결정 수준에서다.** 팀원은 설계 문서를 안 본다, Jira 만 본다. 그래서 이 이슈만 읽고 **무엇을 지켜야 하는지**를 알 수 있어야 한다. **어떻게 만드는지**는 넣지 않는다.

> 수행자가 문서를 못 본다고 치고, 이 이슈만으로 *틀린 방향으로 가지 않고* 일을 시작할 수 있나?

**문서 참조(경로·절 번호)는 이슈에 안 남긴다. 로컬 매핑 파일도 안 만든다.** 대신 **문서 라벨을 반드시 건다** — 이 문서에서 나온 이슈를 찾는 유일한 끈이다. 바뀔 값은 어차피 경계 줄에 복사돼 있어서 값 자체(`300자`)로 검색된다. 절 번호가 하던 일을 값이 한다.

### 하위 작업 템플릿

```
[DATA] 추출기 구현 — 프롬프트 계약·배치·extractor_ver, 3개월 전량 추출 포함

왜   집계가 extraction 을, 유지보수가 new_candidate 를 읽는다.
     모델이 생성하지 않고 선택하게 만드는 지점이다.

완료 기준
  3개월 is_fashion=1 기사 전량에 extraction 행이 있고 실비용이 기록되며,
  범위 밖 인덱스와 본문에 없는 new 는 코드가 버린다.

경계
  · 모델 입력은 제목 + 리드 300자(잠정) + 소제목 전부 + 후보 표. 본문 전문은 주지 않는다.
  · 모델 출력은 {"core":[인덱스...], "new":[...]}. 범위 밖·본문에 없는 것은 버린다 (불변식).
  · 입출력 스키마는 코드가 소유한다. 모델 이름은 설정이다.
  · extractor_ver = 프롬프트 + 사전 + 매칭 방식. 발굴기 버전은 안 들어간다.
```

**경계 줄의 출처는 둘뿐이다.**

1. 문서가 **결정으로 표시한 것** — 불변식 표 · 확정 사항 표 · 파라미터 표(잠정값) · seam 표의 *계약* 열("어디에", 출력이 무엇으로 고정되나).
2. **다른 부품이 기대는 계약** — 테이블 컬럼과 유일성 · 버전 규칙 · 재실행 멱등 · 다른 부품이 부르는 인터페이스.

둘 다 아니면 방법이다. 문서의 서술 절이 "이렇게 한다"고 쓴 것 — 공통 어댑터 · 함수 시그니처 · 어댑터 종류 분류 · 알고리즘 · 내부 단계 순서 — 은 문서가 그린 *한 가지 방법*이지 결정이 아니다. seam 표의 "바꿀 때 건드리는 것" 열도 방법이다. **이 부품 안에서만 끝나는 선택은 전부 수행자 몫이다.** 도구 어휘(오케스트레이터·스케줄러·CLI 의 이름과 용어)도 적지 않는다. 울타리가 없으면 수행자는 어디까지가 자기 결정인지 모르고, 방법까지 적으면 자기 결정이 없어진다. **경계가 열 줄을 넘으면 방법이 섞인 것이다.**

**잠정값은 반드시 표시한다.** 확정값처럼 적으면 나중에 바뀔 때 "왜 말 안 했냐"가 된다.

### 왜 줄 — 층마다 대상이 다르다

- **스토리 → 사용자.** 기능 한 조각이라 사용자 가치가 진짜 있다.
- **하위 작업 → 바로 다음에 이걸 쓰는 부품.** 사용자까지 거슬러 올라가지 않고 한 칸만 간다.

사용자까지 끌고 가면 모든 이슈의 왜가 한 문장으로 같아진다. **구별이 안 되는 정보는 정보가 아니다.** 한 칸만 가면 태스크마다 달라지고, 내가 만든 걸 누가 어떻게 쓰는지 알면 인터페이스를 그쪽에 맞춘다.

### 제목

**스토리** — 짧은 명사구. 사용자 관점은 **본문 첫 줄**로 내린다.

```
키워드 사전 구축
  랭킹에 오를 수 있는 말이 여기서 정해진다. 사전에 없는 말은 어떤 랭킹에도 못 오른다.
```

**하위 작업** — `[파트] 부품 + 동사 — 안에 든 것`. 사용자 관점을 요구하지 않는다.

```
[DATA] 추출기 구현 — 프롬프트 계약·배치·extractor_ver, 3개월 전량 추출 포함
[DATA] 매체 어댑터 4종 구현 — 8개 매체, 3개월 백필 포함
```

**동사를 반드시 넣는다.** `[FE] 연관 키워드 그래프 UI` 는 설계인지 구현인지 스타일링인지 모른다. 대시 뒤에는 이 부품에 흡수된 것을 적는다 — 합친 흔적이 제목에 남아야 "이게 왜 이렇게 크지"가 안 나온다.

**접두어와 라벨이 어긋난 채로 둔다.** 두 어휘가 같은 걸 다르게 부르더라도 통일하지 않는다 — 통일하려면 기존 이슈를 고쳐야 하고 그건 이 스킬의 일이 아니다. 사람 이니셜 라벨은 안 붙인다. 담당자를 비우기로 했으니 앞뒤가 안 맞는다.

### 쓰고 나서 검사 넷

1. **부품 검사** — 완성된 본문에 2단계 신호를 다시 돌린다. 완료 기준이 테이블 경계를 넘나 (둘이다), 판정에 남의 태스크가 필요한가, 경계에 방법이 섞였나.
2. **고유성 검사** — 왜 줄이든 스토리의 사용자 줄이든, **다른 이슈에 갖다 붙여도 말이 되면 실패다.** 그 줄은 이 이슈에만 해당해야 한다.
3. **도구 검사** — 제목·완료 기준·경계에서 도구 이름과 용어(DAG·크론·센서·CLI 명령 등)를 지워도 뜻이 멀쩡해야 한다. 안 멀쩡하면 방법이 섞인 것이다. 도구를 바꿔도 부품 이슈는 그대로여야 한다 — 그게 할당 단위라는 증거다. `[INFRA]` 이슈만 예외다. 인프라는 도구가 곧 대상이다.
4. **출처 검사** — 경계 줄마다 출처를 댈 수 있어야 한다. 어느 결정 표에서 왔나, 아니면 어느 부품이 기대는 계약인가. 못 대면 방법이다. 뺀다. 도구 검사가 못 잡는 것("공통 어댑터가 멱등 삽입을 맡는다", "매체당 함수 둘")을 이 검사가 잡는다.

**완료 기준**: 모든 이슈에 본문이 붙었고 검사 넷을 통과했다.

## 7. Jira 에 등록한다

**여기 오기 전까지 Jira 에 아무것도 쓰지 않는다.** 하위 작업은 부모 없이 못 만들어서 순서가 강제되고, 덕분에 중간에 그만둬도 반쯤 만들어진 이슈가 안 남는다.

1. **새 스토리 생성** — 4·5단계에서 승인된 것만. 부모 에픽은 기존 에픽에서 고른 것.
2. **하위 작업 생성** — 부모 스토리는 필수 필드다.
3. **`Blocks` 링크** — 설계 문서가 순서를 못 박은 곳에만 건다. 부품 사이의 순서다. 이 순서가 이슈에 안 실리면 팀원이 앞 부품 없이 뒤를 시작한다.

채우는 필드는 **부모·라벨·링크뿐이다.**

| 필드 | 이 스킬이 | 왜 |
|---|---|---|
| 부모(스토리) | 채운다 | 하위 작업 필수 |
| 라벨 | 채운다 | 파트 + 문서 라벨. 파트 어휘는 1단계에서 읽은 기존 라벨을 쓴다 |
| `Blocks` 링크 | 건다 | 설계 문서가 못 박은 순서만 |
| 스프린트 | **안 건드린다** | 며칠치를 고르는 건 팀 회의가 할 일. 백로그에 쌓여도 보드는 스프린트에 넣은 것만 뜨니 안 더러워진다 |
| 담당자 | **비운다** | 시작할 때 상태를 옮기고 본인을 담당자로 지정하는 것이 곧 "나 이거 하는 중" 선언이다. 미리 배정하면 그 신호가 죽는다 |
| 우선순위 | 기본값 | `Blocks` 가 이미 순서를 말한다. 두 곳이 순서를 말하면 어긋날 때 어느 쪽이 맞는지 모른다 |
| 스토리 포인트 | 안 채운다 | 이 팀은 안 쓴다 |

**기존 스토리와 에픽은 고치지 않고, 아무것도 지우지 않는다** — 재실행에서 문서에 없어진 태스크가 나와도 표에만 올린다([`references/rerun.md`](references/rerun.md)). MCP 에는 삭제 도구가 없다. 지울 것이 생기면 대상 키 목록(JQL)을 사람에게 준다.

**완료 기준**: 매핑표의 전 행이 등록됐고, 각 이슈에 파트 라벨과 문서 라벨이 붙었다.
