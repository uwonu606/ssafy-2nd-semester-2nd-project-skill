# to-jira

설계 문서를 Jira 하위 작업으로 옮긴다. **bottom-up 이다** — 문서 목차를 따라 내려가지 않고, 해야 할 일을 먼저 다 쪼갠 다음 그것들을 스토리로 묶는다.

**입력은 문서 경로 하나다.** 인자가 없으면 대화 맥락에서 대상 문서를 잡고, 그것도 없으면 사용자에게 묻는다. 대상 문서가 확정되기 전에는 다음 단계로 가지 않는다.

**재실행이면 [`references/rerun.md`](references/rerun.md) 를 읽는다.** 재실행인지는 1단계에서 판별된다 — 그전에는 읽지 않는다.

## 1. 환경을 읽는다

Jira 환경 사실은 이 문서에 없다. **어디를 봐야 하는지만 적혀 있고 무엇이 있는지는 매번 읽는다** — 프로젝트 키도 에픽 목록도 낡는다. Atlassian MCP 도구(JQL 검색)로 아래를 채운다.

- **대상 프로젝트 키** — 접근 가능한 프로젝트가 여럿이면 사용자에게 확인받는다.
- **이슈 타입 계층** — 에픽 / 스토리 / 하위 작업 세 층이 실제로 쓰이는지, 각 층의 타입 이름이 무엇인지.
- **에픽 전량** — 키와 제목. 3단계에서 고를 후보다.
- **스토리 전량** — 키·제목·부모 에픽.
- **기존 하위 작업의 관행** — 제목 접두어와 라벨 어휘. 6·7단계에서 그대로 따른다.
- **문서 라벨로 기존 이슈 검색** — 문서 라벨의 기본값은 문서 파일명 스템이다 (`pipeline-core.md` → `pipeline-core`).

**Atlassian MCP 도구가 없으면 여기서 멈추고 사용자에게 알린다.** 이 스킬은 MCP 없이 할 수 있는 일이 없다.

문서 라벨로 검색된 이슈가 1건 이상이면 **재실행**이다. [`references/rerun.md`](references/rerun.md) 를 읽고 그 분기를 아래 단계에 겹쳐 적용한다.

**완료 기준**: 위 목록이 다 채워졌고, 재실행인지 아닌지가 판별됐다.

## 2. 태스크 초안을 전량 뽑는다

**태스크 경계는 완료 기준 한 줄이 서는 가장 작은 덩어리다.** 태스크마다 완료 기준을 한 줄 쓸 수 있어야 하고, 그 판정에 **다른 태스크가 필요 없어야** 한다.

완료 기준은 코드가 판정한다. **시간 추정은 쓰지 않는다** — 문서만 읽고 "1.5일"이라 적으면 그건 지어낸 숫자다.

셋 중 하나에 걸리면 분할 후보로 ⚠️ 표시한다.

| 신호 | 예 | 왜 크다는 뜻인가 |
|---|---|---|
| 접속사로 판정이 둘 | "소스를 **선정하고** 크롤러를 **구현한다**" | 하나만 끝나도 절반 완료 — 보드에서 구분 안 됨 |
| N개 집합 전체를 건다 | "**8개 매체 전부** 3개월치가 확보된다" | 8번의 서로 다른 실패가 이슈 하나에 뭉침 |
| 판정에 다른 태스크가 필요 | "추출 결과가 정상이다" (사전이 있어야 판정) | 경계 규칙 위반 |

**품질은 완료 기준이 아니다.** "사전이 충분한가", "추출이 정확한가"는 태스크에 안 쓴다. 끌어오면 닫을 수 없는 이슈가 된다. 태스크 완료는 **만들어졌나**까지다.

**조사는 독립 태스크로 안 뗀다.** 조사만 떼면 완료 기준이 "알아냈다"가 되어 코드가 안 붙는다. 구현에 흡수시킨다. 위험이 크면 **스파이크**로 만들고 "돌아가는 조각이 남는다"를 기준으로 삼는다.

**코드로 안 넘어오는 사람 판단은 스토리로 올린다.** 태스크는 코드가 닫는 데까지 쓰고, 사람이 눈으로 보고 판정하는 몫은 그 태스크들을 묶는 **새 스토리의 완료 조건**으로 올린다. 태스크는 전부 코드 판정이라는 규칙이 서고, 사람 판단은 사라지지 않고 한 층 위에 남는다. 이건 **새로 만드는 스토리에만** 쓴다 — 기존 스토리는 안 건드린다.

**완료 기준**: 문서의 할 일이 전부 태스크가 됐고, 각 태스크에 완료 기준 한 줄이 붙었다.

## 3. 태스크를 스토리에 매핑한다

| 층 | 이 스킬이 |
|---|---|
| **에픽** | **절대 만들지 않는다.** 1단계에서 읽은 기존 에픽 중에서 고른다 |
| **스토리** | 기존 것에 붙이는 게 기본. 어느 것에도 안 덮이면 새로 제안하고 **승인**받는다 |
| **하위 작업** | 자유롭게 만든다 |

**에픽 질문은 새 스토리를 만들 때만 생긴다.** 기존 스토리에 붙으면 에픽은 그 스토리의 부모로 이미 정해져 있다.

새 스토리의 에픽은 이렇게 정한다.

- 후보가 하나로 수렴하면 — 매핑표에 **제안 에픽**을 실어 4단계에서 함께 확정받는다.
- 후보가 둘 이상 비등하거나 어느 에픽에도 안 들어맞으면 — ⚠️ 갈림길로 분류해 5단계에서 묻는다.

**완료 기준**: 모든 태스크에 부모 스토리가 정해졌고, 새 스토리마다 에픽이 정해졌거나 ⚠️ 갈림길로 분류됐다.

## 4. 매핑표를 한 장으로 낸다

태스크 전량을 **한 장**에 담아 제시한다. 태스크마다 부모 스토리(기존 키 또는 새 스토리 제안), 파트, ⚠️ 표시를 싣는다.

표 머리에 이번 실행의 **문서 라벨**을 적는다 — 재실행 때 이 라벨로 이슈를 찾으므로, 문서를 개명했거나 앞 실행과 라벨을 잇고 싶으면 사람이 여기서 고친다.

표 아래에 **점검 흔적** 구역을 붙인다.

```
쪼갠 것        [DATA] 매체 어댑터 → 4종으로 분할 · 본문 추출기가 4개라 각각 따로 판정된다
합친 것        엘르·하퍼스바자·코스모 → 1건 · hearst_kr 공통 추출기라 하나만 되면 완료가 아니다
쪼개지 못한 것  [AI] 3개월 전량 추출 → 배치 단위라 더 못 쪼갬 (⚠️ 상한 초과 인지함)
```

**이 구역이 비어 있으면 점검을 안 한 것이다.** 태스크 30개를 뽑았는데 쪼갠 것도 합친 것도 없을 수는 없다. "쪼개지 못한 것"이 0건으로 나오면 오히려 의심한다.

여기서 사람이 자유롭게 수정한다. 고쳐서 돌려주면 그대로 반영한다.

**완료 기준**: 사람이 표를 승인했다.

## 5. ⚠️ 갈림길만 AskUserQuestion 으로 묻는다

표에 ⚠️ 로 남은 것 중 **진짜 갈림길만** 묻는다. 회당 최대 4문항, 전체로 한두 번.

**태스크마다 순회하며 묻지 않는다.** 25~40번 묻게 되면 사람이 전체를 못 본 채 하나씩 판정하고, "이거 너무 잘게 쪼갰는데"를 알아채는 순간이 영영 안 온다. AskUserQuestion 은 선택지를 좁히는 도구라 갈림길에만 쓴다.

**완료 기준**: ⚠️ 가 전부 해소됐다 — 답을 받았거나, 사람이 표에서 직접 고쳤다.

## 6. 이슈 본문을 쓴다

**자족성이 기준이다.** 팀원은 설계 문서를 안 본다, Jira 만 본다.

> 수행자가 문서를 못 본다고 치고, 이 이슈만으로 일을 시작할 수 있나?

*없으면 헤매거나 틀린 방향으로 가는 것*은 넣고, *알면 좋지만 없어도 되는 것*은 뺀다. 전량 복사도 아니고 절 번호만 남기기도 아니다.

**문서 참조(경로·절 번호)는 이슈에 안 남긴다. 로컬 매핑 파일도 안 만든다.** 대신 **문서 라벨을 반드시 건다** — 이 문서에서 나온 이슈를 찾는 유일한 끈이다. 바뀔 값은 어차피 경계 줄에 복사돼 있어서 값 자체(`300자`)로 검색된다. 절 번호가 하던 일을 값이 한다.

### 하위 작업 템플릿

```
[AI] 추출 프롬프트 계약 정의 — 후보 인덱스 입력 / 인덱스 출력

왜   모델이 키워드를 생성하면 표기가 갈려 주간 집계가 쪼개진다.

완료 기준
  기사 하나를 넣으면 {"core":[3,7,12],"new":["..."]}가 나오고
  범위 밖 인덱스와 본문에 없는 new를 코드가 버린다.

경계
  · 모델 입력은 제목·리드(300자)·소제목·후보 목록. 본문 전문은 주지 않는다.
  · 후보마다 출현 횟수와 위치(제목/리드/소제목/본문)가 붙어 있다.
  · 입출력 스키마는 코드가 소유한다. 모델 이름은 갈아끼워도 된다.
  · new는 최대 3개 (잠정 — 승격 문턱 넘는 후보가 충분히 나오는지 보고 조정)
```

**경계는 울타리지 방법이 아니다.** 경계가 자유도를 뺏는 게 아니다 — 울타리가 없으면 수행자는 자유로운 게 아니라 **어디까지가 자기 결정인지를 모른다.**

**잠정값은 반드시 표시한다.** 확정값처럼 적으면 나중에 바뀔 때 "왜 말 안 했냐"가 된다.

### 왜 줄 — 층마다 대상이 다르다

- **스토리 → 사용자.** 기능 한 조각이라 사용자 가치가 진짜 있다.
- **하위 작업 → 바로 다음에 이걸 쓰는 것.** 사용자까지 거슬러 올라가지 않고 한 칸만 간다.

사용자까지 끌고 가면 모든 이슈의 왜가 한 문장으로 같아진다. **구별이 안 되는 정보는 정보가 아니다.** 한 칸만 가면 태스크마다 달라지고, 내가 만든 걸 누가 어떻게 쓰는지 알면 인터페이스를 그쪽에 맞춘다.

### 제목

**스토리** — 짧은 명사구. 사용자 관점은 **본문 첫 줄**로 내린다.

```
키워드 사전 구축
  랭킹에 오를 수 있는 말이 여기서 정해진다. 사전에 없는 말은 어떤 랭킹에도 못 오른다.
```

**하위 작업** — `[파트] 대상 + 동사`. 사용자 관점을 요구하지 않는다.

```
[AI] 추출 프롬프트 계약 정의 — 후보 인덱스 입력 / 인덱스 출력
[DATA] hearst_kr 계열 어댑터 구현 — 엘르·하퍼스바자·코스모
```

**동사를 반드시 넣는다.** `[FE] 연관 키워드 그래프 UI` 는 설계인지 구현인지 스타일링인지 모른다. 그리고 동사가 없으면 2단계의 접속사 신호가 돌 대상이 없다.

**접두어와 라벨이 어긋난 채로 둔다.** 두 어휘가 같은 걸 다르게 부르더라도 통일하지 않는다 — 통일하려면 기존 이슈를 고쳐야 하고 그건 이 스킬의 일이 아니다. 사람 이니셜 라벨은 안 붙인다. 담당자를 비우기로 했으니 앞뒤가 안 맞는다.

### 쓰고 나서 검사 둘

1. **완료 기준 한 줄 검사** — 2단계 3신호(접속사 / N개 집합 / 남의 태스크 필요)를 완성된 본문에 다시 돌린다. 크기를 본다.
2. **고유성 검사** — 왜 줄이든 스토리의 사용자 줄이든, **다른 이슈에 갖다 붙여도 말이 되면 실패다.** 그 줄은 이 이슈에만 해당해야 한다.

**완료 기준**: 모든 이슈에 본문이 붙었고 검사 둘을 통과했다.

## 7. Jira 에 등록한다

**여기 오기 전까지 Jira 에 아무것도 쓰지 않는다.** 하위 작업은 부모 없이 못 만들어서 순서가 강제되고, 덕분에 중간에 그만둬도 반쯤 만들어진 이슈가 안 남는다.

1. **새 스토리 생성** — 4·5단계에서 승인된 것만. 부모 에픽은 기존 에픽에서 고른 것.
2. **하위 작업 생성** — 부모 스토리는 필수 필드다.
3. **`Blocks` 링크** — 설계 문서가 순서를 못 박은 곳에만 건다. 이 순서가 이슈에 안 실리면 팀원이 앞 태스크 없이 뒤를 시작한다.

채우는 필드는 **부모·라벨·링크뿐이다.**

| 필드 | 이 스킬이 | 왜 |
|---|---|---|
| 부모(스토리) | 채운다 | 하위 작업 필수 |
| 라벨 | 채운다 | 파트 + 문서 라벨. 파트 어휘는 1단계에서 읽은 기존 라벨을 쓴다 |
| `Blocks` 링크 | 건다 | 설계 문서가 못 박은 순서만 |
| 스프린트 | **안 건드린다** | 며칠치를 고르는 건 팀 회의가 할 일. 백로그에 쌓여도 보드는 스프린트에 넣은 것만 뜨니 안 더러워진다 |
| 담당자 | **비운다** | 시작할 때 상태를 옮기고 본인을 담당자로 지정하는 것이 곧 "나 이거 하는 중" 선언이다. 미리 배정하면 그 신호가 죽는다 |
| 우선순위 | 기본값 | `Blocks` 가 이미 순서를 말한다. 두 곳이 순서를 말하면 어긋날 때 어느 쪽이 맞는지 모른다 |
| 스토리 포인트 | 안 채운다 | 이 팀은 안 쓴다 |

**기존 스토리와 에픽은 고치지 않고, 아무것도 지우지 않는다** — 재실행에서 문서에 없어진 태스크가 나와도 표에만 올린다([`references/rerun.md`](references/rerun.md)).

**완료 기준**: 매핑표의 전 행이 등록됐고, 각 이슈에 파트 라벨과 문서 라벨이 붙었다.
